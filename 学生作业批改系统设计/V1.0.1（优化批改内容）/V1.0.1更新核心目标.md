# V1.0.1 更新核心目标与开发约定

本文件为本版本规则依据，与同目录的系统总设计图、数据库设计图配套使用。2026-09-22 用户批准实施；实现与接口细节见仓库 README.md、docs/api.md，真实准确率仍需人工实测。

原版V1.0.0存在的问题：
图片经过物理题判断后进入生图模型进行批改时，经常批改错误，错误率极高，将原本正确的改错
现解决方案：
图片经过物理题判断审核的同时输出批改建议，详细告诉生图模型哪些地方需要圈注，以及旁边需要给出的附注。对的题打勾，错的题在错误的地方圈注给出附注。

## 审核模型输出与职责

审核模型只输出两个字段：

- `is_physics`：布尔值，只判断图片是否为物理题，不兼任图片清晰度或是否允许生图的判断字段。统一使用此拼写。
- `grading_advice`：字符串，承载整张图片的批改建议，以及模糊、反光或字迹潦草的处理说明。图片有多题时，所有题目的建议仍放在这一个字符串中，不拆分为逐题对象或数组。

审核模型负责判断作答并给出具体标注指令；生图模型依据原图和批改建议执行标注，不自行重新判断对错，不补写或修改学生原有作答。

拍摄清晰、无反光时的输出示例：

```json
{
  "is_physics": true,
  "grading_advice": "第1题：作答全部正确，在对应答案旁打勾。第2题：学生字迹难以辨认，在对应区域旁标注“？”及“字迹有点潦草哦，可以写清晰一点哦”，不判断该处对错。第3题：动能公式错误，圈注学生所写的“½mv”，旁边批注“动能公式错误，正确公式为 Eₖ = ½mv²”。"
}
```

示例中的公式使用可读文本；若在 JSON 字符串中使用 LaTeX，反斜杠须按 JSON 规则转义，例如 `\\frac{1}{2}mv^2`。

## 上传前提示

在上传区域展示提示：

> 请上传清晰的作业照片，保持对焦，避免反光、阴影遮挡和画面裁切，确保题目与作答完整、公式和上下标可辨认。整页文字过小时，建议分区域拍摄后上传。

## 模糊、反光与字迹潦草的处理

### 拍摄模糊或反光：打回并要求重新上传

- 审核模型通过 `grading_advice` 说明图片模糊、反光等拍摄问题，并提示重新拍摄后上传。
- 已确认是物理题的图片，即使模糊或反光，`is_physics` 仍为 `true`，不能仅因拍摄质量问题改为 `false`。
- 此类图片不进入生图阶段，也不对其中部分题目继续生成批改图；向用户展示重新上传提示。
- 这里的“重试”指重新拍摄并上传清晰图片，不是反复对同一张不合格图片调用模型。
- 图片整体不可辨认时，不强行猜测学科或学生作答，优先提示重新拍摄。

### 拍摄清晰，但字迹潦草：继续批改，难以识别处标注问号

- 对能够可靠辨认的题目或作答部分正常批改。
- 对难以辨认的区域，在附近标注“？”并附温和提示，例如“字迹有点潦草哦，可以写清晰一点哦”。标记不得遮挡原始作答。
- 难以辨认的内容不打勾、不圈错，不根据正确答案猜测学生写了什么。
- 如果无法辨认的内容会影响整题判断，则不对依赖该内容的答案强行判定对错；其他可独立判断的题目继续处理。
- 如拍摄模糊或反光与字迹潦草同时存在，优先按拍摄问题打回，要求重新上传。

## 开发衔接与验收边界

- 是否进入生图阶段不能只看 `is_physics`：物理题也可能因模糊或反光而需要打回。
- 固定规则：拍摄模糊、反光或画面整体不可辨认时，`grading_advice` 必须以 `【重新上传】` 开头，后面写明具体原因和重新拍摄提示。正常批改和单纯字迹潦草不得使用该前缀。
- 数据库新增的附注字段保存完整 `grading_advice`，包括重新上传原因或字迹提示，便于后续人工分析。
- 本版批改准确率通过实际样本测试并由人工检查，不预先承诺准确率数值。检查包括误判对错、模糊或反光图片是否被打回、潦草字迹是否按要求标注，以及生图是否遵循批改建议。

## 登录页面优化
不做账号管理系统，依旧保持V1.0.0现在的输入正确账号和密码直接允许访问。
但是新增一个网页前端页面来输入账号和密码，效验正确后进入批改页面
不改变原账号内容和密码

登录页面需由服务端验证凭据；不能把密码写入前端，也不能仅通过页面跳转保护批改功能。业务接口和图片资源应继续受认证保护，登录页及其必要资源应允许未登录访问。

已确认：用户名不限且可留空，只要原密码正确即可访问，不扩大为账号管理系统。新增 POST /api/auth/login、POST /api/auth/logout、GET /api/auth/session；网页通过 HttpOnly、SameSite=Strict Cookie 维持12小时服务端会话，退出、过期或服务重启后失效。原有 Basic 密码认证继续兼容；退出网页会话不撤销客户端主动发送的 Basic 凭据。不更换或在前端暴露原密码。

## 两字段协议与分流优先级

模型必须返回恰好两个字段的 JSON 对象：`is_physics` 为布尔值，`grading_advice` 为非空字符串，不输出 `reason` 或第三个字段，不输出 Markdown 代码围栏。后端先检查字段、类型及非空要求，失败按模型协议错误处理，不进入生图。

后端对建议首尾去空白后，以 `startsWith('【重新上传】')` 检查固定前缀；不通过正文中是否包含“模糊”“重试”等词语猜测分支。前缀后的原因也不能为空。普通建议中的引用或解释不能触发打回。

| 优先级 | 条件 | 处理与前端提示 |
| --- | --- | --- |
| 1 | 输出格式无效 | `FAILED`，显示“审核未成功，请重试”；不误报为非物理题或模糊 |
| 2 | 建议以 `【重新上传】` 开头，不论布尔值 | `REJECTED`，提示拍摄质量问题和重新拍摄上传；不调用生图 |
| 3 | 无重新上传前缀，`is_physics=false` | `REJECTED`，提示“该图片不是高中物理题，请上传物理作业图片”；不调用生图 |
| 4 | 无重新上传前缀，`is_physics=true` | 保存建议后进入生图；潦草区域的问号和提示也在此分支执行 |

`is_physics` 不因拍摄质量自动变为 false。能确认是物理题时返回 true；能确认不是物理题时返回 false。对于整图不可辨认、学科无法确认的特殊情况，两值布尔无法表达未知，本版约定暂填 false，同时必须带重新上传前缀；此组合仅表示未能确认，不得用于展示“确定非物理题”或统计为已确认非物理题。质量分支始终优先。后续若需要严格保存学科未知状态，再单独评估协议升级。

拍摄质量打回示例：

```json
{
  "is_physics": true,
  "grading_advice": "【重新上传】图片右半部分有反光，无法辨认学生作答，请避开反光并重新拍摄上传。"
}
```

非物理题示例：

```json
{
  "is_physics": false,
  "grading_advice": "该图片不是高中物理题，请上传物理作业图片。"
}
```

整图不可辨认示例：

```json
{
  "is_physics": false,
  "grading_advice": "【重新上传】整张图片过于模糊，无法确认题目内容，请对焦后重新拍摄上传。"
}
```

前端以纯文本展示建议和原因，不把模型文本当作 HTML 执行。展示质量提示时去除开头的控制前缀。前后端采用同一判定表；服务端负责最终决定是否调用生图，不能只依赖前端拦截。

## 数据保存与历史兼容

- `images` 增加 `grading_advice TEXT NULL`，保存规范化后的完整建议，保留固定前缀；正常、潦草、非物理和质量拒绝结果均保存。
- 为在查询接口中恢复两个字段的组合，增加 `is_physics INTEGER NULL CHECK (is_physics IN (0, 1))`。数据库存 0/1，API 转成 false/true；NULL 表示尚无有效审核结果或历史未记录，不能转成 false。
- 初次上传、审核调用或协议失败、历史记录允许两个字段为 NULL。有效结果两个字段在同一事务内保存，同时更新审核状态；保存失败不得继续生图。
- `validation_status=PASSED` 表示允许进入生图，而非仅表示物理相关；质量和非物理拒绝均为 `REJECTED`。学科判断由 `is_physics` 单独表达。
- 两字段均为本版必需保存项，不新增逐题表或批改方案对象。生图尝试表仍只记录实际生图调用；审核拒绝不创建生图尝试。
- 对旧数据库执行可重复运行的增量加列迁移，不能只修改 `CREATE TABLE IF NOT EXISTS`。旧记录不自动补跑模型，不改写原图或既有结果。
- 生图失败保留本次审核结果，重试时复用；不在生图重试期间重新解释或覆盖建议。

## 业务接口增量约定

模型输出只含两个字段，不限制业务接口原有的状态、时间等字段。现有业务接口保持路径、方法及原有字段，按下表扩展：

| 接口 | V1.0.1 约定 |
| --- | --- |
| `POST /api/batches` | 上传请求和原响应保持不变；不接受客户端覆盖模型建议 |
| `GET /api/batches/:id` | 每张图片增加 `is_physics`、`grading_advice`，供前端显示正确的拒绝提示；初始及历史记录可为 null |
| `GET /api/images/:id` | 增加相同两字段，供详情和人工检查；旧字段保留 |
| `GET /api/images/:id/raw` | 原图接口保持不变 |
| `GET /api/images/:id/result` | 仅成功生成后返回结果图，保持现有约定 |
| `POST /api/images/:id/retry` | 仅允许 FAILED；返回 202 及实际进入的 VALIDATING 或 GENERATING 状态，不固定写 GENERATING |

历史 REJECTED 记录若没有建议与学科字段，前端显示“该图片未通过旧版审核，请重新上传”，不猜测新的拒绝原因。

## 状态流转与重试

```text
UPLOADED → VALIDATING
  ├─ 调用/协议失败 → FAILED
  ├─ 质量问题或非物理题 → REJECTED（重新拍摄或更换图片上传）
  └─ 审核通过且结果落库 → READY → GENERATING
                                      ├─ SUCCEEDED
                                      └─ FAILED
```

- `REJECTED` 是本图片处理终态，前端提供“重新上传”，不调用失败重试接口；重新上传创建新图片记录，保留旧记录供分析。
- `FAILED` 且无有效可生成的审核结果：重试进入 VALIDATING，重新审核。历史失败记录缺少建议时也走此分支。
- `FAILED` 且已有 PASSED、true 及无打回前缀的有效建议：重试进入 GENERATING，复用原图和保存的建议。
- `SUCCEEDED` 和 `REJECTED` 调用 retry 仍返回 409；同一图片重复点击只允许启动一次在途处理。
- 技术失败由原有错误响应或错误信息展示，不能误标为图片质量问题。

## 提示词执行约束

审核提示词需同时覆盖两字段协议、分流前缀、整页多题自然语言建议、正确打勾、错误圈注及附注、潦草问号、模糊反光打回。定位采用题号、原文片段和页面位置描述；不要求模型输出逐题对象或坐标。

生图输入固定为原图＋生图提示词＋已保存的 grading_advice。生图模型仅执行标注，不重新判题，不处理重新上传分支，不补全难以辨认的笔迹。删除旧提示词中“正确部分不标记、整页全对写全对”的冲突规则。本版不承诺提示词可以保证像素级不变，原图保真情况由人工实测检查。

## 验收清单

- 上传前清晰度提示可见；清晰正确题正常打勾；错误题圈注并附正确说明。
- 潦草区域出现问号和温和提示，没有凭空补写或强行判错，其他独立可判断题正常处理。
- true＋重新上传前缀、false＋重新上传前缀均显示拍摄质量提示，且生图调用次数为 0。
- false＋普通建议显示非物理题提示，生图调用次数为 0；true＋普通建议进入生图。
- 正文包含“模糊”等词但无前缀时不因关键词误触发拒绝；非法 JSON、空建议或缺字段走技术失败。
- 重新上传和失败重试入口不同；审核失败重试先审核，生图失败重试复用保存的建议。
- 新旧数据库均可启动，迁移重复执行不重复加列，历史记录可读且不自动重跑。
- 接口保留既有路径和方法，前端拒绝提示不再一律显示“非物理题”；登录及图片资源的访问保护不因新增页面失效。
- 使用固定样本人工检查批改结论、原文字迹识别、问号是否适当、建议与生成图是否一致，记录模型及提示词版本。不以接口成功或图片生成成功代替准确率验收，不新增线上二次内容审核。
